Documentação operacional

Use o CRM com IA, com controle.

Conexão, ferramentas e procedimento seguro para uma IA consultar dados, operar conversas e construir fluxos pelo MCP.

Servidor ativo Streamable HTTP Protocolo 2025-06-18 OAuth + token estático
01 · Conexão

Endpoint e credenciais

O endpoint genérico do servidor é:

https://crm.148.113.255.144.sslip.io/api/mcp

Credencial read

Para relatórios, leitura de conversas, métricas, contatos, conexões e inspeção de fluxos. Não expõe ferramentas de escrita.

Credencial write

Permite alterações compatíveis com as permissões do usuário: criar fluxos, enviar mensagens, mover cards e outras operações.

OAuth

Para clientes interativos, crie uma credencial OAuth no CRM e use a URL individual:

https://crm.148.113.255.144.sslip.io/api/mcp/ID_DA_CREDENCIAL

Token estático

Envie o token no cabeçalho de todas as chamadas:

Authorization: Bearer ${CRM_MCP_TOKEN}
Segredo: nunca coloque o token em prompts, documentação, commits ou logs. O token estático só aparece uma vez, na criação.
02 · Inicialização

O que a IA deve fazer primeiro

  1. Executar initialize.
  2. Executar tools/list.
  3. Ler description, inputSchema e annotations antes de usar cada ferramenta.
  4. Buscar IDs pelas ferramentas de listagem. Nunca inventar UUIDs.
  5. Ler o estado atual antes de alterá-lo.
  6. Após escrever, reler ou validar o recurso.
A lista é dinâmica. Uma ferramenta ausente normalmente indica credencial somente leitura, permissão insuficiente ou usuário sem vínculo ativo com a empresa.
03 · Segurança

Limites para o agente

Leia antes de editar

Use get_flow e as consultas equivalentes antes de qualquer alteração.

Valide e simule

Um fluxo deve passar por validate_flow e simulate_flow antes da ativação.

Impacto real

send_message e trigger_flow alcançam clientes reais. Exigem pedido explícito.

Destruição

Ferramentas delete_* e remoções de nós, ações ou conexões exigem confirmação explícita.

  • Use client_message_id ao enviar mensagens para impedir duplicação.
  • Valores *_cents estão em centavos: R$ 49,90 é 4990.
  • Não prossiga se o resultado MCP tiver isError: true.
  • Nunca adivinhe tipos de bloco, ações, configurações ou handles.
04 · Fluxos

Como construir um fluxo

  1. Chame get_flow_block_catalog sem argumentos para descobrir os tipos de nó.
  2. Consulte cada node_type que pretende usar e leia ações, exemplos, schemas e handles.
  3. Crie o rascunho com create_flow.
  4. Leia o resultado com get_flow para descobrir o nó inicial e a definição atual.
  5. Monte incrementalmente com add_flow_node, add_node_action e connect_nodes, ou substitua o grafo inteiro com save_flow_definition.
  6. Leia o fluxo novamente e confira nós, ações e arestas.
  7. Execute validate_flow e corrija todos os erros.
  8. Execute simulate_flow e percorra os caminhos relevantes.
  9. Mostre um resumo ao usuário.
  10. Só execute activate_flow após autorização explícita.

Regras do grafo

  • entry aponta para o nó inicial.
  • Uma saída possui somente um destino.
  • Handles comuns incluem source, timeout, other, failure, success, option:<id> e output:<chave>.
  • O handle correto deve vir do catálogo ou de get_flow.
  • save_flow_definition substitui todo o rascunho. Preserve todos os elementos existentes.

08 · Agente

Prompt pronto

Você opera o CRM exclusivamente pelas ferramentas MCP disponíveis.

No começo da sessão, liste as ferramentas e leia os schemas. Nunca invente IDs,
tipos de bloco, ações, configurações ou handles. Antes de editar um fluxo, leia-o
com get_flow. Antes de criar ou alterar blocos, consulte get_flow_block_catalog.

Faça leituras diretamente. Antes de escrever, informe resumidamente o que será
alterado. Não envie mensagens reais, não dispare nem ative fluxos e não execute
ações destrutivas sem autorização explícita. Para fluxos: crie em rascunho,
valide, simule, apresente o resultado e só então peça autorização para ativar.

Após cada escrita, releia o recurso ou use a validação correspondente. Se uma
ferramenta retornar isError, explique o erro e pare o encadeamento dependente.
Não exponha tokens, segredos ou dados sensíveis em respostas ou logs.
Sonda · Ofertas e arquivos capturados

Consultar e baixar funis da Sonda

Use list_spy_offers para escolher uma oferta pelo ID e get_spy_flow ou get_spy_offer para ler o roteiro, resumo, conversas e catálogo de mídias. O ID da oferta é diferente do ID de um fluxo CRM.

  • list_spy_probes: sondas, chips e status.
  • get_spy_probe_messages: conversa de uma sonda pelo ID dela.
  • list_spy_media: arquivos disponíveis de uma oferta.
  • download_spy_media: bytes de PDF, áudio, imagem ou vídeo pelo ID da mídia.
  • export_spy_offer_zip: pacote com resumo, roteiro, conversas e mídias capturadas.
  • import_spy_offer_to_crm: cria uma nova cópia em rascunho editável com as mídias; exige escrita e flows.edit. Cada chamada cria uma cópia.

Downloads retornam JSON com data em base64, total_bytes, sha256, next_offset e expires_at. Comece com offset=0; repita com o next_offset devolvido até ele ser null. Decodifique cada parte e concatene os bytes em ordem. Confira o SHA-256 do arquivo final. O padrão é 256 KiB; length aceita até 1 MiB. A cópia permanece estável por cinco minutos; se expirar, reinicie em offset=0. O pacote inclui apenas arquivos efetivamente capturados.

Consultas e downloads exigem flows.view. A ponte só atende à empresa proprietária da Sonda; instalações com várias empresas precisam definir CRM_SPY_COMPANY_ID.

09 · Saúde

Checklist do servidor

  • Endpoint sem token responde 401 com WWW-Authenticate.
  • Os documentos OAuth em /.well-known/ respondem JSON.
  • initialize devolve leonas-crm.
  • tools/list mostra somente o permitido para a credencial.
  • Uma leitura simples, como list_connections, retorna conteúdo válido.
  • O uso atualiza last_used_at.
  • Token revogado responde 401 imediatamente.
